# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install       # install dependencies
npm run dev       # start Vite dev server (localhost:5173)
npm run build     # production build to dist/
npm run preview   # serve the dist/ build locally
```

There is no lint or test setup in this repo.

## Architecture

This is a single-page Vite + Svelte 5 (runes) app — no SvelteKit, no router — that renders a MapLibre GL JS terrain map of Vermont.

- **`src/lib/mapStyle.js`** builds the full MapLibre style object (sources + layers) once, consumed by `MapView.svelte` at map init. `TERRAIN_SOURCES` is the list of interchangeable `raster-dem` sources: `dem` (bare-earth, VCGI pmtiles on S3, unsuffixed layer ids — the default), `dsm` (VCGI surface model including buildings/canopy), and `mapterhorn` (Mapterhorn's global 1m DEM, loaded via its `tilejson.json` endpoint rather than pmtiles). Every DEM-derived layer (`hillshade`, `hypsometric-tint`, `elevation-tint-above`, `elevation-tint-below`) is generated once per entry in `TERRAIN_SOURCES` via `sourceIdFor()`/`layerIdFor()`, so adding a fourth terrain source only means adding one entry to that list plus its source definition — no new per-layer code. `ControlsPanel.svelte`'s "Terrain source" segmented control (one pill per `TERRAIN_SOURCES` entry, radio inputs wired as a mutually-exclusive group via `bind:group`) drives which set is visible via the shared `terrainSource` string state (one of the `TERRAIN_SOURCES` keys); switching it loops over every source and layer type rather than tracking "previous vs. new" by hand.
- Elevation highlighting ("highlight above/below elevation") and hypsometric tinting both use the `color-relief` layer type. The stops baked into `mapStyle.js` for the above/below layers are inert transparent placeholders, not real defaults — the actual color expression is only ever set at runtime via `map.setPaintProperty(..., 'color-relief-color', ...)` in `ControlsPanel.svelte`. Any code path that flips a tint layer's visibility must also call the matching `updateTintAboveExpression()`/`updateTintBelowExpression()`, or the layer renders fully transparent even when "on".
- **`src/lib/vtBoundary.js`** exports `VT_BOUNDARY_RING`, a polygon ring used as a hole in the `vtMask` geojson source (a world-covering polygon with Vermont cut out) so imagery/terrain outside the state boundary is masked with the background color.
- **State ownership**: `MapView.svelte` creates the `maplibregl.Map` instance in `onMount` and exposes it upward via `bind:map`. `App.svelte` only mounts `ControlsPanel` and `ProfilePanel` once `map` is non-null, and owns the cross-component shared state (`is3d`, `terrainSource`, `profileArmed`) that both children read/write via `bind:`.
- **`ProfilePanel.svelte`**'s elevation-profile tool calls `map.queryTerrainElevation()`, which only returns real values while terrain is active. If 3D view is off when a profile is drawn, it temporarily calls `map.setTerrain(...)`, samples, then calls `map.setTerrain(null)` again — it does not touch the `is3d` state itself. It waits for `map.isSourceLoaded(sourceIdFor(terrainSource))` rather than the `idle` event before sampling — `idle` blocks on every active source (imagery overlay included), which scales badly with a long-distance profile drawn while zoomed out. `queryTerrainElevation()` isn't itself a usable readiness signal: MapLibre returns a placeholder elevation (not `null`) for tiles still loading, so polling it directly gives false-positive "ready" results.
- **Vite + maplibre-gl gotcha (dev)**: `maplibre-gl` must stay in `vite.config.js`'s `optimizeDeps.exclude`. If it gets pre-bundled, its worker script 404s and hillshade/terrain rendering fails silently — the map still loads (background, mask, imagery) but shows no relief, with no console error to point at.
- **Vite + maplibre-gl gotcha (production build)**: maplibre-gl resolves its worker script's URL at runtime from `import.meta.url` via a dynamic string, which Rollup can't statically detect, so `npm run build` never emits `maplibre-gl-worker.mjs` (or the `maplibre-gl-shared.mjs` it imports) into `dist/` on its own — only `npm run dev` works out of the box, since there maplibre-gl is served unbundled straight from `node_modules`. Without both files the worker fails to load and dies within milliseconds of being created; hillshade/terrain again renders as a flat background with no console error, this time only in a genuine production build (`npm run build && npm run preview`, or any real static-host deploy) — `npm run dev` gives no warning of it. `vite.config.js`'s `copyMaplibreWorker()` plugin copies both files from `node_modules/maplibre-gl/dist/` into `dist/assets/` on every build to fix this; if maplibre-gl adds/renames its worker-side files on a version bump, this list needs updating to match.
- **`vite.config.js`'s `base: './'`**: needed because this app is deployed under an arbitrary subpath (not domain root) in at least one hosting target. Without it, built asset references are root-absolute (`/assets/...`) and 404 under any subpath. If this is ever hosted at domain root only, this can be dropped, but relative `base` works in both cases so there's no reason to.
- `pmtiles`'s `Protocol` must be registered with `maplibregl.addProtocol('pmtiles', ...)` before the map is constructed (done in `MapView.svelte`); the VCGI DEM/DSM sources are addressed with `pmtiles://` URLs. The `mapterhorn` source is a plain HTTPS TileJSON endpoint instead — no pmtiles protocol involved.
- **Attribution control** (`MapView.svelte`): `customAttribution` must be nested under the `attributionControl` option, not passed as a top-level `Map` constructor option (silently dropped otherwise) — see maplibre-gl's `AttributionControlOptions` type. There's no public option to start the compact attribution collapsed (only to auto-collapse below 640px), so `MapView.svelte` forces it into the collapsed state right after construction by removing MapLibre's internal `maplibregl-compact-show` class/`open` attribute — a workaround tied to those internal class names, which could break on a maplibre-gl upgrade.
